# rep-mind-map

> Интерактивная mind map для JS/TS репозитория. Один взгляд — и архитектура проекта как на ладони.

---

## Идея проекта

Когда приходишь в чужой проект или возвращаешься к своему после нескольких месяцев — нужно время, чтобы снова понять, как всё устроено. Файлы, функции, зависимости между ними — всё это живёт в голове у автора, но не у тебя.

**rep-mind-map** решает эту проблему визуально: анализирует структуру локального JS/TS репозитория и строит интерактивный граф, где каждый файл — нода, каждый импорт — ребро. Граф можно исследовать, перетаскивать ноды, кликать и смотреть детали функций прямо в браузере.

---

## Границы проекта

Проект намеренно узкий и сфокусированный. В скоупе:

- Локальные JS/TS репозитории (передаётся путь к папке)
- Визуализация файловой структуры и зависимостей между файлами
- Отображение экспортируемых функций и классов внутри нод
- Интерактивный граф с drag-and-drop и кликом на ноду для деталей

Вне скоупа (на данном этапе):

- GitHub URL и удалённые репозитории
- Поддержка других языков (Python, Go и др.)
- Анализ runtime-поведения — только статика через AST
- Встроенный редактор кода

---

## Цели и задачи

**Цель:** дать разработчику мгновенное визуальное понимание архитектуры JS/TS проекта без чтения кода вручную.

**Задачи:**

1. Реализовать Node.js сервер, который рекурсивно обходит файлы репозитория
2. Построить AST-парсинг через `acorn` / `@typescript-eslint/parser` для извлечения импортов, экспортов, функций и классов
3. Сформировать граф в формате `{ nodes, edges }` и отдать его через HTTP
4. Отрисовать граф в браузере через SVG + D3.js (force simulation + drag)
5. Реализовать интерактивность: клик на ноду показывает список функций/классов внутри файла
6. Обеспечить читаемость графа при 20–300 нодах

---

## Стек

| Слой | Технология | Зачем |
|---|---|---|
| Сервер | Node.js + `fs` | Чтение файлов локального репо |
| Парсинг | `acorn` / `@typescript-eslint/parser` | AST — точный анализ кода без regexp |
| Транспорт | HTTP (встроенный `http`) | Отдаёт граф на фронт |
| Визуализация | SVG | DOM-элементы, нативные события |
| Физика и drag | D3.js | Force simulation + drag из коробки |
| Фронт | Vanilla JS | Никаких лишних фреймворков |

---

## Как это работает

```
Локальный репозиторий
        │
        ▼
  Node.js сервер
  └── рекурсивный обход файлов
  └── AST-парсинг каждого файла
  └── построение { nodes, edges }
        │
        ▼
    HTTP ответ (JSON)
        │
        ▼
   Браузер (SVG + D3)
   └── force simulation расставляет ноды
   └── drag-and-drop для перестановки
   └── клик на ноду → детали файла
```

## Драйверы и мотивация

**Проблема онбординга.** Каждый разработчик тратит часы на изучение чужого проекта. Текстовые файлы плохо передают архитектуру — мозг лучше воспринимает визуальные связи.

**Проблема возврата к проекту.** Свой код через 3 месяца — как чужой. Граф восстанавливает контекст за секунды.

**Минимализм как принцип.** Никаких тяжёлых IDE-плагинов, облачных сервисов, регистраций. Одна команда — и граф в браузере.

**Инструмент разработчика, сделанный разработчиком.** Без лишнего UI, без магии — прозрачный стек, который легко форкнуть и доработать под себя.
